# Dependency Mapper - Source of Truth

**Purpose:** To map dependencies and architectural connections between microservices across the `infra-gitops` ecosystem and visually display them.

## Requirements Constraints
As extracted from the `/grill-me` protocol:

1. **Data Source:** The Dependency Mapper does NOT parse raw code files or helm charts directly. It relies on SBOMs (Software Bill of Materials) generated by existing software in the cluster (e.g., Trivy Operator `SbomReport` CRDs).
2. **Dependency Scope:** Codebase Dependencies (Libraries, Docker base images, Golden Path CI templates).
3. **Frontend Visualization:** Interactive Node Graph using `reactflow` (or similar) to visually drag and explore topologies.
4. **Data Persistence:** The parsed relationships from SBOMs and GitLab are persisted in PostgreSQL to query historical changes and maintain high performance.

## Architecture Guidelines
- **Backend (.NET 8):** Must query Kubernetes `SbomReport` resources and persist `DependencyNode` and `DependencyEdge` representations in Postgres via EF Core.
- **NuGet `NU1605` OpenAPI Transitive Floor Guard:** `Microsoft.AspNetCore.OpenApi 8.0.32` requires `Microsoft.OpenApi >= 1.6.31`. Whenever `Microsoft.OpenApi` is referenced directly in `dependency-mapper/backend/DependencyMapper.Backend.csproj` (to remain `< 2.0.0` for `Swashbuckle.AspNetCore 6.9.0`), its version MUST be `>= 1.6.31` so `dotnet restore` never fails with `error NU1605: Detected package downgrade`.
- **Frontend (React):** Must implement `reactflow` and connect to the backend REST API (`/api/graph`) to visualize the topology.
- **Kubernetes RBAC:** The backend `ServiceAccount` needs `ClusterRole` permissions to `get, list, watch` the `sbomreports.aquasecurity.github.io` CRDs.
